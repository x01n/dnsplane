## 简介

DNSPlane 是一个**单二进制交付**的 DNS 运维平台，把三件事收在同一套进程里：

- **多厂商 DNS 统一管理**：以一套 15 方法的 `dns.Provider` 接口屏蔽 22 家服务商差异，域名与解析记录的读、写、启停、批量操作走同一抽象。
- **证书自动化**：ACME v2 客户端与云厂商证书渠道双轨签发，签发结果按 `issue_time` 变化自动推送到部署器实现（CDN、面板、服务器）。
- **容灾监控与切换**：1 秒 tick 的常驻调度器按 ping/tcp/http/https 探测主源，连续失败达阈值后改写云端解析记录，主源恢复后自动回切。

配套能力为多用户权限体系与基于 shadcn/ui 的响应式控制台，另对外提供 API Key 鉴权的 `/api/v1` 开放接口。面向的使用者是同时管理多家 DNS 服务商、需要周期性续签并下发证书、且希望解析记录随源站健康状态自动切换的运维与平台团队。

### 容灾监控与自动切换

`monitor.New()` 在 `main.go:105` 赋值到全局 `Service` 并立即 `Start()`。主循环是 1 秒 ticker（`monitor.go:107-127`），`dispatchTasks` 以 `active` 为 1 且 `check_next_time` 到期为唯一调度条件，按该列升序取 `maxDispatchPerTick = 100` 条（`:24`、`:144-179`），用 `processing.LoadOrStore` 去重，到期时间顺延一个 `frequency`。探测并发受信号量 `maxConcurrentChecks = 64` 限制（`:29`），等待期间 ctx 超时即判失败。

决策链：主源健康则 `err_count` 清零，若已切换且开 `auto_restore` 则回切；主源异常则 `err_count` 加一，达 `cycle` 且未切换才 `smartSwitch`（`:411`）。切换按 `DMTask.Type` 分派：0 暂停原记录、1 删除并留存原值、2 直接切备用值。`ManualSwitch`（`:711`）走同一套逻辑。状态最终由一条合并 UPDATE 写回（`:334`），该调用未处理返回错误。

### 认证授权与会话链

五种认证方式共用一套 JWT 双令牌：口令、TOTP、magic link、OAuth、API Key。access 与 refresh token 分别 AES-GCM 加密后写入 cookie（`middleware/auth.go:296`，`EncryptForCookie` 见 `:45`、`DecryptCookie` 见 `:66`），校验时 cookie 解密结果必须与 `Authorization: Bearer` 逐字相等（`Auth()` 起于 `:125`）。每个用户同一时刻只保留一个有效 refresh JTI，重用检测失败即清空该用户全部 refresh。

权限模型三维度组合：`users.level` 角色（0 自助注册、1 第三方创建、2 及以上管理员）、`users.permissions` JSON 模块点、`permissions` 表的域名加子域加只读委派（`models.go:10`、`:105`）。控制台链的 `Permission`（`router.go:104`）写入 `perm_read_only` 与 `perm_sub_domain` 上下文供下游拦截。

对外链用 HMAC-SHA256 替代 cookie，`APIKeyAuth` 挂在组级（`apiv1/router.go:30`），签名即身份与完整性凭据，因此该链刻意不继承 CSRF，理由写在 `apiv1/router.go:11-23` 注释块。字段级加密由 `crypto` 提供 AES-256-GCM，密钥从 `security.master_key` 派生；配置写入权限固定 `0600`、目录 `0700`（`config.go:156-170`）。

| 手段 | 实现 | 参数 | 证据 |

前端为纯静态导出（`output: 'export'`、`trailingSlash: true`、`images.unoptimized`，`next.config.ts:4-8`），零 Node 运行时、镜像极小；`typescript.ignoreBuildErrors` 已移除（`:9-13`），类型错误中断构建，这是 CI 上唯一真实的质量门禁。约束是任何服务端渲染能力都无法引入。

## 结论

### 优势与局限

优势：一套 `dns.Provider` 抽象覆盖 22 家厂商，使控制台操作与厂商解耦；`notify` 的 `Channel` 注册表是开闭原则的干净实现，渠道与配置键全部由注册表推导、装载方零硬编码、重复注册即 panic；单二进制加 distroless 使交付只需一个文件与一个可写目录；`X-Request-ID`、`X-Error-ID`、`db_queries`、`logs.db` 四件套可把一次请求的 SQL 与堆栈串起来；Redis、MySQL、密钥生成三条路径都有明确降级或兜底。

局限集中在六处：

- **持久化契约与模型脱钩**：`AutoMigrate` 新库缺少 `DMTask` 运行期仍读写的列，新装实例 `err_count` 恒 0，永不切换、告警、回切。
- **证书链密钥治理缺口**：ACME 账户密钥未持久化触发 CA 限流；PEM 下载把私钥明文写入请求日志。
- **注册表口径分裂**：`cert` 表混装真实工厂与表单占位工厂，`deploy` 三套编号口径并存，靠白名单与后缀猜测对齐。
- **`cert/ucloud` 未编入二进制**：`main.go:27-30` 缺该行 blank import，该包 `init()` 永不执行。
- **对外 API 缺硬约束**：145 条端点无入口限流，签名未绑定请求体。
- **巨型文件与零测试**：`handler/cloudflare.go` 2509 行等多处远超单文件 500 行约束，`cert/deploy` 共 18998 行无测试文件；`build.yml` 全程无 `go test`、`npm test`、lint 步骤，79 个测试文件未被流水线利用。

另有既存文档偏差：README 的账户接口方法与路由不符（`README.md:134-135` 对比 `router.go:113-117`），并把已实现的华为云、百度云、火山引擎标为「待实现」（`README.md:103-105`）。
