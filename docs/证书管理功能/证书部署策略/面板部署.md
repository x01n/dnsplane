## 简介

面板部署是证书部署器体系中面向「服务器控制面板 HTTP 接口」的一类实现：不登录机器、不写
文件，把已签发的 `fullchain` 与 `privateKey` 提交给面板，由面板完成落盘与生效。相比 SSH /
FTP / 本地文件三条「服务器类」通道，面板通道把「站点识别」与「重载」两件事交给面板，因此
DNSPlane 侧的实现重心全部压在认证与会话维持上。

本文覆盖 16 个注册名，按认证形态分四族：

- **密钥 + MD5 签名族**：`btpanel`、`btwaf`、`btwin`、`opanel`、`xp`。令牌形如 `md5(时间戳 + md5(密钥))`，宝塔系走表单、WAF 与 1Panel 走请求头
- **HMAC-SHA256 令牌族**：`acepanel`、`ratpanel`、`amh`。签名覆盖方法、路径、查询串与请求体摘要，密钥不出现在请求中
- **账号密码会话族**：`cloudpanel`、`qzyun`、`nginxproxymanager`、`kangle`、`kangleadmin`。先登录取 Cookie 或 JWT，再带会话调业务接口
- **直连凭证族**：`directadmin`（Basic）、`axisnow`（Bearer）、`mwpanel`（appid + secret）

**能力边界**（依据实读代码）：面板类部署器**全部不发送重载命令**——对 `btpanel.go`、
`cloudpanel.go`、`directadmin.go`、`qzyun.go`、`axisnow.go` 与 `panels/` 三文件执行重载
关键词检索，命中为零；重载语义仅存在于 `servers/ssh.go:154-214` 与
`servers/local.go:66-131`。面板地址与密钥属机密，库内加密存储，本文示例一律脱敏为 `{占位}`。
6 个部署器固定开启 TLS 校验跳过，见[性能考虑](#性能考虑)。行号以当前工作区文件为准。

## 核心组件

### 面板 API 客户端

每个面板实现都是独立 `net/http` 客户端，构造点在工厂函数内。`ErrUseLastResponse` 是会话族
必需品：CloudPanel 与 DirectAdmin 用 3xx 表达「登录成功」，允许自动跟随会让重定向后的
HTML 污染判定（`cloudpanel.go:154-170`）。

| 注册名 | 客户端位置 | 超时 | 重定向策略 | 认证载体 |
| --- | --- | --- | --- | --- |
| `btpanel` | `providers/btpanel.go:40` | 30s | 默认跟随 | 表单 `request_token` |
| `btwin` | `panels/btwin.go:32` | 60s | 默认跟随 | 表单 `request_token` |
| `cloudpanel` | `providers/cloudpanel.go:47-64` | 30s | `ErrUseLastResponse` | Cookie + CSRF |
| `directadmin` | `providers/directadmin.go:49-74` | 20s | `ErrUseLastResponse` | HTTP Basic |
| `qzyun` | `providers/qzyun.go:62-82` | 30s（双客户端） | `ErrUseLastResponse` | Cookie + Server Action |

### 站点识别

面板侧没有统一的「域名 → 站点」抽象，各实现自行解析：

- 宝塔 v0 把站点名直接传给 `/site?action=SetSSL`，不需要 ID（`btpanel.go:280-286`）
- 宝塔 v1 与 `btwin` 必须先查 `datalist` 换 `siteid`，不命中即报「站点不存在」（`btpanel.go:326-351`、`btwin.go:72-88`）
- CloudPanel 把域名拼进路径 `/site/{domain}/certificate/import`，站点是否存在由返回页面是否为登录页反推（`cloudpanel.go:181-192`）
- DirectAdmin 用 `CMD_API_SSL` 的 `domain` 字段，合法性在客户端预校验（`directadmin.go:107-117`、`:185`）
- NPM 走「证书 ID 优先、域名反查 Proxy Host 兜底」双路径（`nginxproxymanager.go:66-124`）

### 证书写入

写入动作都是「一次 HTTP 提交证书链 + 私钥」，差异在字段名与封装：宝塔 v1 用 `cert`/`key`，
宝塔 v0 用 `csr`/`key`（`btpanel.go:244-292`），CloudPanel 用 `site_import_certificate[...]`
嵌套数组（`cloudpanel.go:202-209`），DirectAdmin 把私钥拼在证书之前一并提交
（`directadmin.go:105`），全栈云用 `multipart/form-data` 的 Server Action 字段
（`qzyun.go:152-157`）。

### 重载

面板通道没有重载组件。宝塔在设置 SSL 时自行让站点生效，DNSPlane 不再干预；需要在部署后
执行自定义命令的场景必须另建 SSH 或本地任务。这决定了面板任务与服务器任务常需成对配置：
前者保证证书进入面板，后者保证面板之外的 nginx 或证书池同步。

## 详细组件分析

### 宝塔面板 `btpanel`

注册于 `providers/btpanel.go:20`，表单 `config_selfhosted.go:11-32`。账户字段 `url`、
`key`（可回退 `api_key`）、`version`；任务字段 `type`、`sites`、`is_iis`。签名机制为
`request_token = md5(request_time + md5(apiKey))`（`:106-111`），`md5Hex` 见 `:24-28`，
认证字段与业务参数同层以表单编码提交。

`version` 决定端点集合：v0 用 `?action=` 查询串风格，v1 用 REST 风格路径。

| 部署目标 | v0 端点 | v1 端点 | 参数名差异 |
| --- | --- | --- | --- |
| 站点证书 | `/site?action=SetSSL` | `/site/set_site_ssl` | v0 `csr`/`key`，v1 `cert`/`key` |
| 面板证书 | `/config?action=SavePanelSSL` | `/config/set_panel_ssl` | v0 `certPem`，v1 `ssl_pem` |
| 邮局证书 | `/plugin?action=a&name=mail_sys&s=...` | 同 v0 | 额外 `domain`/`act` |
| Docker 站点 | `/mod/docker/com/set_ssl` | 同 v0 | 额外 `site_name` |
| 连通性检查 | `/config?action=get_config` | `/config/get_config` | 无 |

分派代码见 `:229-254`（面板）、`:258-292`（站点）、`:295-308`（邮局）、`:311-323`（Docker）、
`:138-159`（检查）。

**站点识别约束**：v1 的 `getSiteID` 以 `table=sites`、`search_type=PHP`、`p=1`、`limit=10`
拉列表后按 `name` 精确匹配（`:326-350`）。不翻页且限定 10 条，站点在首页之外会误报
「站点不存在」；`search_type=PHP` 对纯静态站点可能不命中。

**IIS 限制与双层错误检查**：`Deploy` 对 `is_iis=true` 直接返回「IIS站点部署需要PFX证书，
当前版本暂不支持」（`:169-171`），而表单 `config_selfhosted.go:30` 提供「是」选项，属表单
能力与实现能力不一致。`httpRequest` 在状态码 ≥400 时取 `msg` 或 `message` 拼错误（`:84-92`），
`request` 再检查 `status == false` 的业务失败分支（`:125-131`）——宝塔 API 常在 200 响应里
带 `status: false`，这层双检必要。

### DirectAdmin `directadmin`

注册于 `providers/directadmin.go:27`，表单 `config_selfhosted.go:445-461`。面板族中认证最
规范的实现：HTTP Basic（`:402`），凭据可为账户密码或 Login Key，表单 `Note` 已声明
（`config_selfhosted.go:451`）。

**地址强校验**：`directAdminValidPanelURL` 要求 HTTPS 且不得带路径、userinfo、查询或片段。
工厂函数无法返回错误，故把错误缓存在 `configErr` 字段，由 `Check`/`Deploy` 首行报出
（`:49-55`、`:121-124`）。这是 Go 工厂签名受限下的标准解法。

**私钥格式转换**：DirectAdmin 不接受 PKCS#8 ECC 私钥。`directAdminNormalizePrivateKey`
检测 `-----BEGIN PRIVATE KEY-----` 前缀，解析后判断是否 ECDSA，是则手工重写 DER 结构为
SEC1（`:214-238`）；DER 元素读取与长度编码由 `daReadDERElement`（`:323`）与
`daEncodeDERLength`（`:354`）支撑，未引入 ASN.1 依赖。RSA 与已为 SEC1 的 ECC 原样透传。

**响应解析**：DirectAdmin API 返回查询串而非 JSON，`directAdminParseResponse` 按首字符判定
走 JSON 还是 `directAdminParseQuery`（`:417-441`），401/403 单独映射为「认证失败，请检查
用户名和认证密码」（`:418-420`）。提交形式为 `action=save`、`type=paste`、
`certificate = 规范化私钥 + "\n" + fullchain`（`:105-113`）。

### CloudPanel `cloudpanel`

注册于 `providers/cloudpanel.go:22`，表单 `config_selfhosted.go:426-442`。CloudPanel
**没有对外 API**，实现是模拟浏览器登录后台并 POST 导入表单，因此设置浏览器 User-Agent
（`:283`）与 `Origin`/`Referer`（`:287-293`）。

**登录**：`GET /login` 取页面 → `cloudPanelExtractValue` 正则抠 `_csrf_token`（`:135`、
`:370`）→ 以 `orderedForm` 提交。`orderedForm` 是显式有序键值对类型（`:241-250`），因为
面板侧用 PHP `http_build_query` 严格校验字段顺序，`url.Values` 的字典序编码会导致校验失败。
登录后若重定向命中 2FA 路径或页面含 2FA 标记，直接返回「暂不支持」（`:150-152`、`:406-414`），
表单 `Note` 已提前声明（`config_selfhosted.go:431`）。

**导入与判定**：路径 `/site/{domain}/certificate/import`，域名用自定义编码
`cloudPanelRawURLEncode`（`:464`）而非 `url.PathEscape`，以匹配面板对点号的处理。表单字段为
`site_import_certificate[privateKey]` 等嵌套形式，`certificateChain` 固定留空——`fullchain`

### ACE Panel 与 AMH

## 性能考虑

**超时预算分层**。外层统一 5 分钟 `context.WithTimeout`（`task_runner.go:345`、
`cert_deploy.go:843`），内层客户端 20s 至 60s，CloudPanel 与全栈云还按调用点施加 15s/20s/30s
子超时（`cloudpanel.go:273-277`、`qzyun.go:650-654`）。多站点循环时超时**共享**而非按站点
分配：CloudPanel 每站点至少 2 个请求，加登录 2 个，`sites` 超过 20 行容易顶到上限。

**请求放大**。全栈云最严重：首次部署的动作 ID 发现会下载页面内所有同源 JS
（`qzyun.go:462-483`），单个构建产物可达数 MB；绑定域名还会二次 `GET /certificate`
（`:282-283`）。动作 ID 缓存在实例字段 `p.actions`（`:458-460`），但部署器实例每任务重建，
**缓存不跨任务复用**，同一账户密集任务会重复支付该开销。

**连通性检查异步且不回写**。`DeployAccountCheck` 用 `utils.SafeGo` 起协程，HTTP 立即返回
「提交成功」（`cert_deploy.go:311-323`），检查超时仅 30s（`:314`），结果只写后端日志，不回
写账户状态——**前端看不到检查结论**，属观测缺口。

**TLS 校验跳过清单**。6 个部署器固定 `InsecureSkipVerify: true`：`cloudpanel.go:49`、
`directadmin.go:58`、`qzyun.go:80-81`（两个客户端都跳）、`synology.go:42`、`proxmox.go:39`、
`k8s.go:301`。风险是部署时把 `fullchain + privateKey` 发往可被中间人改写的对端，而 `ssh.go`
已实现主机密钥校验，两者标准不一致。**建议**：改为可选开关，默认校验，允许自签面板用户显式
关闭；此项记为已知风险，不在本文范围内修改。

**重试、告警与回写**。失败时 `task_runner.go:354-360` 取 `MaxRetry`（为 0 时默认 5），仅当
「重试次数 +1 达上限」才通知，中间失败静默；非幂等的面板操作（全栈云新增证书分支
`qzyun.go:234-251`）在重试下可能产生多余证书条目。反向价值是 `qzyun` 把 24 位 ID 写回
`info.Config`（`:177`）让下次部署跳过名称查找，而 `AxisNow` 只写 `info.Data`
（`axisnow.go:123`），每次续期都需重新派生名称。

### 部署成功但证书未生效

按序排查：

1. **部分成功掩盖失败**。CloudPanel 与 ACE Panel 只要有 1 个站点成功即返回成功
   （`cloudpanel.go:91-107`、`acepanel.go:49-66`），必须逐行读 `cert_deploys.log_content`
2. **AxisNow 名称漂移**。证书名由 `NotBefore` 派生（`axisnow.go:137`），续期后会新建一张
   证书而非更新原证书；若平台侧绑定旧证书，表现为「部署成功但未生效」
3. **面板侧未重载**。宝塔的站点、Docker、邮局三个分支生效路径不同（`btpanel.go:183-224`），
   面板 API 不负责面板之外的组件
4. **NPM 证书类型不符**。只更新 `provider=other` 的自定义证书（`nginxproxymanager.go:73`、
   `:108`），绑定内置 Let's Encrypt 的 Proxy Host 不会被改动

### 新增面板适配器的最小清单

1. 在 `providers/` 或 `panels/` 建文件，`init()` 内 `base.Register("name", NewXxxProvider)`
2. 嵌入 `base.BaseProvider`，只实现 `Check`/`Deploy`（及可选 `SetLogger`）
3. 需回写任务配置则实现 `DeployWithInfo` 并写 `info.Config`；仅展示写 `info.Data`
   （`base.go:60-74`、`:152-183`）
4. 表单加进 `config_selfhosted.go`，`Class` 用 `ClassSelfHosted`；账户级放 `Inputs`，
   任务级放 `TaskInputs`
5. 客户端超时显式设置，禁止用 `http.DefaultClient`；不引入第三方 HTTP 封装库
6. 站点与域名解析用 `base.SplitDomains` 或 `base.GetConfigDomains`，不重复实现切分

## 结论

面板部署是部署器体系中**形态最杂的一组**：16 个注册名对应 4 种认证范式，其中 CloudPanel
与全栈云甚至没有 API，靠 HTML 表单自动化与前端构建产物逆向撑起来。

**做得好的**：DirectAdmin 的地址强校验加 `configErr` 缓存（工厂无法返回错误时的正确解法）、
手写 PKCS#8 → SEC1 避免 ASN.1 依赖；NPM 的三级寻址与「冲突不猜测」；AxisNow 的全分支实现与
错误聚合；`qzyun` 把「首次填名称、后续用 ID」做成可自愈回写闭环。

**应改的**：宝塔 `getSiteID` 的 `limit=10` 单页假设（`btpanel.go:331`、`btwin.go:73`）会产生
「站点不存在」的假阳性；6 处 `InsecureSkipVerify` 与 `ssh.go` 的主机密钥校验标准不一致；
CloudPanel 与 ACE Panel 的「任一成功即成功」使 `cert_deploys.status` 无法表达部分失败；
`DeployAccountCheck` 结果只进日志不回写，界面看不到连通性结论。

**架构层面**：`providers/` 与 `panels/` 的目录分野已失去语义（`qzyun.go:267` 跨面板复用
`cloudPanelRawURLEncode` 可证）；`btpanel` 与 `btwin` 存在成段重复（签名、站点查询、SSL
提交），按 DRY 可抽出「宝塔协议客户端」，但优先级低于上述假阳性问题。

面板与服务器通道的取舍是清晰的：**能用官方 API 就不写文件**，**面板没有 API 才做表单自动化**
（接受上游改版风险），**两者都不足才退回 SSH**（唯一能执行重载命令的通道）。

### 相关文档与术语

同级的 SSH 与本地文件部署是**唯一支持重载命令的两条通道**，面板任务与它们常需成对配置。
`deploy/README.md:7-20` 的目录结构（列 `interface.go`、`executor.go`）与文件计数
（providers 16、panels 15）与当前代码不符，应以代码为准。

| 术语 | 含义 |
| --- | --- |
| 面板 | 服务器控制面板（宝塔、1Panel、DirectAdmin 等），非 DNSPlane 自身前端 |
| 站点寻址 | 把证书对应到面板内某个网站的过程，可按名称、ID 或域名 |
| 会话族 | 需先登录换取 Cookie 或 Token 才能调业务接口的面板 |
| Server Action | Next.js App Router 的服务端动作端点，全栈云的调用目标 |
| 部分成功 | 多站点循环中只要一个成功即整体返回成功的语义 |
| 回写 | 部署器把新生成的 ID 写回 `cert_deploys.config` 供下次使用 |
