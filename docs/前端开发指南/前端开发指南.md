## 简介

DNSPlane 前端为 Next.js 16.2.4 应用，运行于 React 19.2.4 + TypeScript 5，样式基座为 Tailwind CSS v4 与 shadcn/Radix 组件族。项目采取纯静态导出模式：`output: 'export'`、`trailingSlash: true`、`images.unoptimized: true`，产物 `web/out/` 通过 `scripts/sync-main-web.cjs` 全量复制到 `main/web/`，再由 Go 侧 `//go:embed all:web` 打进单二进制。

贡献者需理解两条构建路径的差异：

- 本地开发使用 `npm run dev`，Next.js 走 Turbopack 增量编译。
- 交付与 CI 构建必须走 `npm run build:ci`，Next.js 显式指定 `--webpack` 并调用 Node 同步脚本。Windows 专有的 `npm run build` 依赖 `set` 与 `powershell`，不参与跨平台流水线。

## 详细组件分析

### 本地开发环境与构建入口

**运行时基线**：CI 与容器镜像统一锁定 Node 22（`.github/workflows/build.yml:50` `node-version: "22"`，`Dockerfile:4-10` `node:22-bookworm-slim`）。仓库同时保留 `web/bun.lock`，贡献者可选择 Bun 作为包管理器，但 CI 与 Dockerfile 的权威入口是 `npm ci`，两者锁定的依赖树必须等价。

**脚本矩阵**（对应 `web/package.json:5-11`）：

| 命令 | 定义 | 真实行为 | 适用场景 |
| --- | --- | --- | --- |
| `npm run dev` | `next dev --turbopack` | Turbopack 增量编译，HMR 快速 | 本地开发 |
| `npm run build` | `set "ANALYZE=true" && next build && powershell ...` | Windows 专有：`set` 环境变量 + `powershell` 拷贝 `out` → `../main/web` | 仅 Windows 本机 |
| `npm run build:ci` | `next build --webpack && node scripts/sync-main-web.cjs` | 显式 webpack + Node 跨平台同步 | CI 与 Linux/macOS 本地唯一推荐入口 |
| `npm run start` | `next start` | 本地服务端渲染启动 | 本项目为 `output: 'export'`，`start` 不适用于产物分发 |
| `npm run lint` | `eslint` | 静态检查 | PR 提交前 |

**Turbopack 与 webpack 的差异**：

- Turbopack 面向开发场景，增量编译快、支持模块热替换，但不保证与生产构建产物字节等价；`dev` 路由的 `useSearchParams` 边界缺失通常不会立刻报错。
- `--webpack` 用于 CI 与 `build:ci`，会真正执行 `next build` 的静态导出流程，触发 `generateStaticParams`、类型检查、ESLint 与 `export` 落盘。贡献者若只在 `dev` 下自测，可能漏掉 `output: 'export'` 对 `dynamic = 'force-dynamic'`、`headers`、`middleware` 等特性的禁用。

**推荐验证组合**（提交前）：

```bash
cd web
npx tsc --noEmit
npm run lint
npm run build:ci
```

### TypeScript 严格模式与 199 类型错误清零

`web/tsconfig.json:7` 开启 `strict: true`，同时 `noEmit`、`moduleResolution: bundler`、`jsx: react-jsx`、`target: ES2017` 构成当前编译口径。Next.js 官方插件 `next` 与路径别名 `@/*` 一并启用。

**历史事件 v1.0.11**（见 `docs/Chanlog.md:37-67`）：

- v1.0.7 时代，`next.config.ts` 曾配置 `typescript.ignoreBuildErrors`，类型错误被静默吞掉。安全审计 H-2 认定该开关会让 XSS、原型污染、越权类型混淆穿透到运行时。
- v1.0.7 移除该开关后，`npx tsc --noEmit` 暴露出 **199 个**存量类型错误。
- v1.0.11 提交 `72e15a9` 用 7 个文件清零全部 199 项，本地构建重新跑通。
- 文档重建时在 2026-10-10 工作区快照复验：`npx tsc --noEmit` 退出码 0，无输出。

**贡献者守则**：

- 不得在 `next.config.ts` 重新引入 `typescript.ignoreBuildErrors`。
- 单个文件若确需绕过类型检查，必须就地使用 `// @ts-expect-error` 局部豁免并写明理由，禁止 `// @ts-nocheck` 文件级禁用。
- API 返回的 `id` 字段在不同后端路径可能表现为 `number` 或 `string`，`lib/api.ts` 的类型契约必须与后端实际返回一致（v1.0.7 曾因此触发 CI 拦截）。

```typescript
// web/lib/api.ts 示意：后端 ID 契约需与实际响应对齐
export interface Domain {
  id: number
  name: string
  accountId: number
}
```

### ESLint 与静态检查

`web/eslint.config.mjs` 采用 ESLint 9 Flat Config，叠加 `eslint-config-next` 的两套预设：

```javascript
import { defineConfig, globalIgnores } from "eslint/config";
import nextVitals from "eslint-config-next/core-web-vitals";
import nextTs from "eslint-config-next/typescript";

const eslintConfig = defineConfig([
  ...nextVitals,
  ...nextTs,
  globalIgnores([
    ".next/**", "out/**", "build/**", "next-env.d.ts", "scripts/**",
  ]),
]);

export default eslintConfig;
```

**覆盖范围**：

- `core-web-vitals` 预设：强制 `<Image>`、`<Link>`、`next/head` 等约定，捕获影响 LCP/CLS 的反模式。
- `typescript` 预设：与 `tsconfig.json` 联动的类型层规则，如未使用变量、不安全类型断言。
- `globalIgnores`：`scripts/**` 不在应用代码范围（`sync-main-web.cjs` 是 Node 工具，不参与浏览器运行）。

**提交前检查**：

```bash

npm run lint
```

### 目录约定与命名规范

App Router 的路由组使用括号语法：`(auth)`、`(dashboard)`，二者不进入 URL 段。真实路由入口在 `web/app/page.tsx`（客户端 `useEffect` 中 `router.replace('/login')`）、`web/app/(auth)/login/page.tsx` 等。

| 约定项 | 规则 | 依据 |
| --- | --- | --- |
| 页面文件名 | 一律 `page.tsx`，实现体超过 500 行需拆 `client.tsx` 伴生 | 项目「单文件 500 行」上限 |
| 路由组 | `(auth)` `(dashboard)`；括号目录不参与 URL | Next.js App Router |
| 动态段 | `[id]/page.tsx` + `[id]/client.tsx` 薄壳分离 | `output: 'export'` 需要 `generateStaticParams` 占位 |
| 服务端组件 | 默认 Server Component；需要 hooks 时文件首行 `'use client'` | React 19 RSC 约定 |
| 错误边界 | 每层路由组挂 `error.tsx` `loading.tsx`，根层挂 `global-error.tsx` | Next.js 错误处理 |
| 路径别名 | `@/*` → 项目根 | `tsconfig.json:21-23` |
| 组件命名 | 具名 + kebab-case 文件名；类型 `PascalCase` | 现有 `components/` 风格 |
| Hooks 命名 | `use*`，集中在 `lib/hooks.ts` | `useTurnstileGate`、`useDashboardUser` 等 |

### 新页面开发流程

以「新增一个 `dashboard/reports` 页面」为例，标准 7 步：

1. 在 `web/app/(dashboard)/dashboard/reports/page.tsx` 建立入口。若页面需要浏览器 API 或 hooks，首行 `'use client'`。
2. 若主体超过 500 行，拆分实现到 `web/app/(dashboard)/dashboard/reports/client.tsx`，`page.tsx` 仅做转发。
3. 若页面接入动态段（如 `reports/[id]`），必须同时提供：
   - `export const dynamicParams = false`
   - `export function generateStaticParams() { return [{ id: '_' }] }`
   - `client.tsx` 通过 `window.location.pathname` 或 `usePathname()` 运行时解析真实 id
4. 在 `web/app/(dashboard)/layout.tsx:55-93` 的 `navigation` 常量中新增一项，指定 `name` `href` `icon` 与 `module`；若仅管理员可见，加 `adminOnly: true`。
5. 在 `web/lib/api.ts` 补齐 API 与类型契约（若后端接口未定，先在后端仓库落定后再补），前端只允许调用 `api.request` 或已封装的 `domainApi/accountApi/certApi` 等命名空间。
6. 若使用 `useSearchParams`，必须外包 `Suspense`（参考 `reset-password/page.tsx:340-348`、`magic-login/page.tsx:26-29`）。这是 `output: 'export'` 场景下最容易被忽略的约束。
7. 提交前依次运行 `npx tsc --noEmit`、`npm run lint`、`npm run build:ci`；`build:ci` 通过意味着产物已成功同步到 `main/web`。


## 性能考虑

- **静态导出与预渲染**：`output: 'export'` 强制所有页面在构建期完成 prerender，浏览器拿到的是纯 HTML + `_next/static`。首屏依赖 CDN/边缘缓存，`trailingSlash: true` 保证目录形态匹配 Go 侧静态资源路由。
- **动态段的成本**：`generateStaticParams` 只生成 `id='_'` 一个占位 HTML，其余 id 复用同一份静态壳，运行时由 `client.tsx` 正则解析 `window.location.pathname`，避免构建期枚举全部 domain 的爆炸成本。
- **包体控制**：Radix 与 lucide-react 通过 Next.js tree-shaking 与 `next build --webpack` 的 sideEffects 分析按需拆分；`components/large` 单文件超过 1500 行（如 `domains/[id]/client.tsx` 1799 行、`settings/page.tsx` 2102 行、`monitor/page.tsx` 2100 行）需评估代码分割或懒加载。
- **验证码懒加载**：`GoCaptchaDialog` 通过 `dynamic import` + `Suspense` 挂载（`login/page.tsx:20` 附近），避免首屏拉入 `go-captcha-react` 主包。
- **useSearchParams 边界**：`output: 'export'` 下 `useSearchParams` 必须外包 `Suspense`，否则构建告警且会引发整页 fallback。已正确包裹的位置：`reset-password/page.tsx:340-348`、`reset-totp/page.tsx:216-224`、`magic-login/page.tsx:26-29`、`magic-login/totp/page.tsx:21-23`、`app/layout.tsx:24-26`（`RouteProgress`）。
- **401 合并刷新**：`lib/api.ts:26-27` 的 `refreshInFlight` 将并发 401 合并为单次 `POST /auth/refresh`，避免 JTI 轮转互相踩掉新 token。
- **图像策略**：`images.unoptimized: true`，Next.js Image 不走 CDN 优化管道，需自行控制 `public/` 图片大小。

## 结论

DNSPlane 前端以 Next.js App Router + 纯静态导出为基座，通过 `build:ci` + `sync-main-web.cjs` + Go `embed` 三段式与后端交付解耦。贡献者需重点关注三件事：**本地 Turbopack 与 CI webpack 的差异不得混用**、**TypeScript 严格模式的历史 199 错误清零不可倒退**、**`output: 'export'` 场景下 `useSearchParams` 与动态段 `generateStaticParams` 的强制约束**。

未来的迭代方向（YAGNI 原则下按需推进）：

- 拆分 `settings/page.tsx`（2102 行）、`monitor/page.tsx`（2100 行）、`domains/[id]/client.tsx`（1799 行）等超大单文件，收敛到项目 500 行上限以内。
- 评估 `components/captcha-dialog.tsx`（233 行无引用）与 `go-captcha-dialog.tsx` 的重复实现，保留一份。
- 若 CI 需并行化，可将 `next build --webpack` 与 `go build` 拆分为两个作业，通过 `actions/cache` 传递 `main/web`。
